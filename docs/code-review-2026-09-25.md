## Замечания

### 1. P1 — тест и спецификация расходятся с данными галереи

В [`tests/app.test.mjs:21`](../tests/app.test.mjs#L21) проверяются 3 карточки «до/после», а [`src/data/portfolio.ts:79-110`](../src/data/portfolio.ts#L79) содержит 6 элементов. Компонент выводит все элементы без ограничения ([`BeforeAfterSection.tsx:35-38`](../src/components/BeforeAfterSection.tsx#L35)). [`DESIGN_SOURCE.md:18`](../DESIGN_SOURCE.md#L18) также описывает 3 карточки. Поэтому текущий `npm test` падает. Нужно выбрать утверждённое число карточек, привести данные и тест к одному требованию и проверить состав изображений. Простая замена `3` на `6` в тесте скроет расхождение со спецификацией.

### 2. P1 — тяжёлые изображения «до/после» без вариантов размера

Шесть PNG из `src/assets/before-after` занимают **14 346 103 байта (13,68 MiB)**; каждый — 2,22–2,55 МБ при ширине около 1620 пикселей. [`BeforeAfterSection.tsx:7`](../src/components/BeforeAfterSection.tsx#L7) отдаёт один исходный файл для любого экрана, без `srcset`/`sizes`. `loading='lazy'` откладывает загрузку, но при прокрутке пользователь получает весь объём. При утверждённых трёх карточках сначала убрать лишние изображения из отображаемых данных; для оставшихся подготовить сжатые WebP/AVIF и размеры под реальные ширины карточек. Проверить визуальное качество после конвертации.

### 3. P2 — подписи, категории и фотографии противоречат друг другу

У элемента [`src/data/portfolio.ts:50-55`](../src/data/portfolio.ts#L50) заголовок про архитектуру бровей, категория `lash-ext`, а `imageAlt` описывает наращивание ресниц. Само изображение `IMG_4812.PNG` показывает лицо и брови. Ещё пример: элемент [`src/data/portfolio.ts:63-69`](../src/data/portfolio.ts#L63) озаглавлен как окрашивание и коррекция бровей, но помечен `lash-lam`, а alt описывает ресницы. Англоязычные alt-тексты в русскоязычной странице выглядят как описания для генерации изображения. Это уже ухудшает доступность; при появлении фильтров неверные категории приведут к неправильной выдаче. Сверить каждый заголовок, категорию и alt с фактическим снимком; сделать alt краткими и русскоязычными. Исправить опечатки в названиях услуг при этой сверке.

### 4. P2 — модель категорий не используется, хотя фильтры есть в спецификации

[`src/data/portfolio.ts:19-25`](../src/data/portfolio.ts#L19) задаёт `PortfolioCategory`, и все карточки получают `category`, но [`PortfolioSection.tsx:32-35`](../src/components/PortfolioSection.tsx#L32) выводит список целиком без чтения категорий. [`DESIGN_SOURCE.md:17`](../DESIGN_SOURCE.md#L17) предусматривает пять фильтров. Сейчас поля выглядят как рабочая функция, но на поведение не влияют. Решить по актуальному требованию: реализовать фильтрацию с проверкой категорий либо убрать пока неиспользуемую модель. Сначала исправить ошибки данных из пункта 3.

### 5. P2 — заголовок карточки используется как React key

[`BeforeAfterSection.tsx:36-38`](../src/components/BeforeAfterSection.tsx#L36) и [`PortfolioSection.tsx:33-35`](../src/components/PortfolioSection.tsx#L33) используют `item.title` как ключ. В данных уже встречаются близкие и повторяющиеся названия: «Корекция + Окрашивание» и «Коррекция + Окрашивание» ([`src/data/portfolio.ts:85-108`](../src/data/portfolio.ts#L85)). Исправление опечатки создаст одинаковые ключи. Добавить стабильный `id`, независимый от отображаемого текста.

### 6. P3 — оставлены файлы и настройки стартового шаблона

[`src/App.css:1-182`](../src/App.css#L1) содержит стили `.counter`, `.hero`, `#next-steps` и прочих элементов шаблона, но нигде не импортируется; эти 182 строки не участвуют в странице. [`README.md`](../README.md) всё ещё описывает стандартный Vite-шаблон вместо текущего проекта. Удалить неиспользуемый CSS и заменить README краткими командами и описанием структуры. Перед удалением проверить отсутствие ссылок на файл в других инструментах проекта.

### 7. P3 — дублирование разметки и контактных данных

[`PortfolioSection.tsx:4-15`](../src/components/PortfolioSection.tsx#L4) и [`BeforeAfterSection.tsx:3-20`](../src/components/BeforeAfterSection.tsx#L3) повторяют каркас карточки, тень, фон и часть классов. Телефон и почта отдельно зашиты в [`HeroSection.tsx:57-74`](../src/components/HeroSection.tsx#L57) и [`SiteFooter.tsx:10-18`](../src/components/SiteFooter.tsx#L10). Сейчас объём дублирования небольшой; общий компонент карточки оправдан только если их оформление должно меняться синхронно. Контакты полезно хранить в одном месте уже сейчас, чтобы не допустить расхождения при обновлении.

### 8. P3 — два подключения одного набора иконок

[`index.html:16-22`](../index.html#L16) дважды подключает `Material Symbols Outlined` с разными наборами осей. Это лишний запрос таблицы стилей и затрудняет понимание того, какая декларация задаёт итоговый шрифт. Оставить одну конфигурацию с нужными осями и `display=swap`.
